## Browser client — `packages/browser/clickstream.js`

One file, ~1,200 lines, plain JavaScript, no dependencies, no build step. Runs
as a classic script tag.

### Capture

- 16 typed event reporters: `pageView`, `search`, `categoryView`, `facetApply`,
  `facetRemove`, `sortChange`, `resultClick`, `productView`, `addToCart`,
  `removeFromCart`, `cartView`, `checkoutStart`, `checkoutStep`, `orderSubmit`,
  `login`, `logout`
- `track()` for any event in the taxonomy; unknown names are dropped rather
  than sent
- `identify()` merges session-wide dimensions; empty values delete rather than
  overwrite
- `money()`, `config()`, `identity()`, `flush()` helpers

### Discovery attribution

- `discoveryId` minted on `search` and `category_view`
- Facet and sort changes narrow a listing without starting a new discovery
- `result_click` pins the listing context plus 1-based rank to a specific
  product
- `product_view` / `add_to_cart` / `remove_from_cart` read the pin, falling
  back to the current listing, then to `direct`
- Immutable snapshots — a later facet click cannot rewrite an earlier
  product's recorded filters
- Pinned-product map capped at 50 with least-recently-touched eviction
- State in `sessionStorage`, surviving full page navigations
- Cleared on `logout`

### Identity

- `anonymousId` in `localStorage`, durable per browser
- `sessionId` in `sessionStorage` with a 30-minute inactivity window
- v4 UUIDs from `crypto.randomUUID`, falling back to `getRandomValues`, then to
  `Math.random`
- No fingerprinting of any kind
- Optional in-browser SHA-256 of `customerRef` via `hashCustomerRef`, with case
  and whitespace normalisation, and one digest per distinct address per batch

### Transport

- Batching with a configurable linger, and an immediate send at 50 events
- `fetch` with `keepalive`, falling back to `XMLHttpRequest`
- `sendBeacon` on `pagehide` and on `visibilitychange` to hidden
- Immediate flush on `orderSubmit` and `login`
- Events dropped rather than retried, so a session's event order cannot be
  scrambled by a retry queue

### Automatic instrumentation

- Page views on load and on `pushState` / `replaceState` / `popstate` /
  `hashchange`
- URL-based page classification across 10 page types, with locale-prefix
  stripping and a `classify` override hook
- Search-term extraction from `q`, `query`, `search`, `s`, `keyword`, only on
  pages classified as `search`
- Deferred and cancellable, so a site reporting a search itself is not
  double-counted
- Result count omitted rather than defaulted to zero when unknowable

### Declarative instrumentation

- Delegated `data-clickstream` click listener covering 12 event types
- `closest()` traversal, so a click on an icon inside a button still resolves
- Compact `data-facets="color:blue,size:m"` selection parsing
- Minor-unit price parsing with currency normalisation

### Resilience

- Every public method wrapped; nothing throws into the host page
- Storage probed once per store, with an in-memory fallback for private
  browsing modes that throw on access
- Missing `site` logs a warning and sends nothing
- Install-stub replay for calls made before the file loads

## Install stub — `packages/browser/snippet.js`

Readable form of the inline stub. Queues calls as `[method, args]`, guards
against double installation, and appends the deferred script tag.

## Shared contract — `packages/shared/`

- `events.js` — the 16 event types, 10 page types, the 5-step funnel definition,
  human labels, and the product-event list
- `wire.js` — per-event validation with reasons, per-event rejection so one bad
  call site does not cost a batch, clock-skew clamping beyond 24 hours, string
  capping at 512 characters, batch cap at 50, body cap at 256 KB

## Collector — `apps/server/src/`

- `node:http` only; `pg` is the single runtime dependency
- **Ingest is authenticated.** `POST /collect` requires a bearer token,
  compared in constant time
- Refuses to start with no credential, and refuses a key under 24 characters —
  an open write endpoint fails invisibly, since the reports look normal
- Opt-in browser-direct mode authenticated by `Origin` against a per-site
  allowlist, which is required to be non-empty; warns on every start while on
- Distinct refusals: 401 for a token problem, 403 for an origin problem, so a
  silent analytics failure is diagnosable
- Authorization runs before the database is touched, so a refused write leaves
  no shopper or session row
- `POST /collect` with per-site CORS, a 60-second origin cache, and preflight
- `GET /c.js` and `/clickstream.js` serving the client with a 5-minute cache
- `GET /snippet.js`
- `GET /health`
- Unknown site → 404, inactive site → 403, so a script-tag typo is loud
- 202 responses listing rejected events, visible in the browser's network tab
- One transaction per batch; one multi-row insert for all its events
- Shopper and session upsert, with `COALESCE(EXCLUDED, existing)` so a later
  batch carrying no store cannot erase one an earlier batch established
- Session dimensions taken from the last event that supplies each, so a
  mid-session sign-in lands on the session row
- Order lines split into `order_items` for per-product revenue attribution
- Device classification from the user agent into three buckets
- Rejections recorded to `ingest_errors`, trimmed on write to a configurable cap

## Reports admin — `apps/server/src/`

Read-only; no route writes anything.

- 17 reports: Overview, Funnel, Searches, Zero-result searches, Search to
  product, Revenue by discovery, Filters and facets, Categories browsed,
  Products, Bought together, Fulfilment mix, Store performance, Orders, Pages,
  Sign-ins, Sessions, Install health
- Market-basket pairs from `order_items`: co-occurrence count, the attach rate
  in both directions, and lift against independent popularity
- Every table sortable by clicking a header, on the raw value rather than the
  formatted text, with empty cells held at the bottom in both directions
- Session journey view — one visit's full ordered trail with plain-language
  event summaries
- Shared segment filters: site, named range, explicit from/to, device,
  signed-in vs anonymous, store, channel, customer, row limit
- One `scoped` CTE behind every report, so a segment means the same thing
  everywhere
- Every query parameterised; no filter value interpolated into SQL
- `/reports.json` publishing the catalog and column types
- `/events` and `/install` reference pages
- Generic renderer driven by column type: text, number, money, percent, date,
  code, journey link
- Server-rendered HTML, inline CSS, light theme, no client framework
- Optional shared-password gate; a satisfied gate is sufficient authorization,
  so there is one secret to distribute rather than two
- Gate half-configured (one of `GATE_SITE` / `GATE_AUTH_URL`) refuses to start
- Constant-time admin token comparison; refuses all requests when unconfigured
- HTML escaping on every value, plus a restrictive `Content-Security-Policy`
- Currency-aware money formatting from minor units

## Schema — `apps/server/migrations/`

- `sites`, `shoppers`, `sessions`, `events`, `order_items`, `ingest_errors`,
  `schema_migrations`
- Wide `events` table: 44 columns, typed for every dimension a report slices
  by, JSONB for the long tail
- 11 indexes including partial indexes on query, sku, category, facet,
  discovery and customer
- `ON DELETE CASCADE` throughout, so deleting a shopper removes their data
- Both a client timestamp and an arrival timestamp, plus a batch sequence
  number to order events sharing a millisecond
- `BIGINT` and `NUMERIC` parsed to JS numbers at the driver

## Omnichannel

- Closed set of five fulfilment methods: delivery, pick-up, curbside, reserve,
  ship-from-store. Case and spacing normalised; anything outside the set dropped
- Physical location as a stable key plus a denormalised name, kept separate from
  the session's sales channel
- Fulfilment recorded from `add_to_cart` onward, not only on the order, so an
  abandoned basket that wanted a store is still visible
- Order lines carry their own fulfilment and location, falling back to the
  order's — a mixed basket can ship one line and hold another
- **Fulfilment mix** report: the aggregate, stating what share of revenue the
  store network carried
- **Store performance** report: the same business split by location
- Revenue computed from order lines rather than order totals, so a mixed basket
  is not credited entirely to one method

## Traffic generator — `tools/traffic/`

- One behaviour model, two drivers: `synth` posts events directly (weeks of
  history in under a minute), `browser` drives a real page with Playwright
- Emits an abstract intent script, so backfilled and browser-driven data are the
  same shape, and the accuracy check is exact rather than statistical
- Five shopper personas; the funnel is an outcome of the mix, not a dice roll
- `--dry-run` prints the persona mix, the funnel it implies, and a sample
  session translated to events
- Deterministic, with per-session derived seeds so concurrency cannot change the
  output
- Recency-weighted history and a two-peak hour-of-day curve
- Returning-shopper pool, so shoppers are meaningfully fewer than sessions
- Weighted device mix, so the reports are not all desktop
- Store-fulfilment choice drawn from what each location actually offers
- Store profiles are one JSON file and carry no hostname
- Baskets that hold more than one thing: a second line is drawn from what that
  shopper actually looked at (another opened product, or a neighbour from the
  listing they browsed), not from the whole catalog — what makes the Bought
  together report's pairs mean something instead of reflecting raw popularity
- `--loop` mode keeps generating traffic indefinitely at a configurable
  `--rate-per-minute` after the opening burst, for a demo whose reports need
  to look alive during a live meeting rather than seeded once and static
- `reconcile.js` compares the action log against captured data field by field,
  classifying findings as missing-session, missing-events, wrong-field or
  extra-events; its exit code gates a scheduled job
- `reconcile.js` has its own unit suite (`reconcile.test.mjs`, `drivers/browser.test.mjs`
  — 15 tests) covering skipped-step field attribution and the browser driver's
  race-condition waits (facet chip class, URL settling, PDP render before
  dwell); not part of a workspace, so `npm test` / `npm run predeploy` does not
  run it

## Operations

- Migration runner: filename-ordered, one transaction per file, recorded and
  idempotent, naming the file on failure
- Migrations applied on boot; safe to run concurrently
- `MODE=collect|admin|both`, so the internet-facing and private halves deploy
  separately
- Fails before binding the port when Postgres is unreachable
- Graceful shutdown draining in-flight requests, with a 10-second cap
- Retention job deleting in 5,000-row batches, off by default
- `npm run site:add` to register or update a site
- `npm run db:create` for local setup
- Deterministic seed generator producing realistic funnels, zero-result
  searches, returning shoppers and mixed devices, pushed through the real
  ingest path
- `Dockerfile` with dependency-layer caching

- Home, search, category, product, cart, checkout, order confirmation, sign-in
